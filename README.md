# 골든벨 (HTML · CSS · JavaScript · SQL 버전)

Node.js 서버 + PostgreSQL 로 도는 실시간 골든벨이다.
여러 기기(휴대폰 · 노트북 · 프로젝터)가 같은 게임에 함께 참여한다.

## 폴더 구조

```
goldenbell-web2/
├── index.html          첫 화면 (역할별 링크)
├── html/
│   ├── join.html       참가 등록  (진행측 노트북)
│   ├── play.html       접속 + 게임 (참가자 휴대폰)
│   ├── screen.html     프로젝터   (대형 화면)
│   ├── login.html      관리자 로그인
│   └── admin.html      진행자 콘솔 (PC)
├── css/
│   └── style.css       전체 디자인
├── js/
│   ├── store.js        서버 통신 + 실시간 수신 (SSE)
│   └── app.js          화면 그리기 + 버튼 동작
├── server/
│   ├── db.js           PostgreSQL 연결 (접속 정보는 .env 에만)
│   └── server.js       Express + API + 실시간 전송
├── db/
│   ├── 001_schema.sql     표 · 함수 · 트리거 · 안전 뷰 · 팀 8개 (전부 지우고 새로 짓는다)

└── scripts/
    ├── migrate.mjs     SQL 파일을 번호순으로 실행
    └── create-admin.mjs 진행자 계정 만들기
```

### 코드의 `ponytail:` 주석

일부러 단순하게 만들고 넘어간 자리에 붙여둔 표시다.
"여기는 이 한계까지만 버틴다, 넘어가면 이렇게 바꿔라"를 적어둔 것이라
나중에 손볼 곳을 찾을 때 `ponytail:` 로 검색하면 된다.

```
server/server.js   진행자 세션을 메모리에 둔다 → 서버를 여러 대로 늘리면 DB 세션 표로
server/server.js   기본 PIN 을 1234 로 고정 → 외부 공개 행사면 무작위 4자리로
server/server.js   정적 파일 캐시를 끈다 → 규모가 커지면 파일 이름에 번호를 붙이는 방식으로
js/app.js          상태가 바뀔 때마다 내 정보를 한 번 더 물어본다 → 수백 명이면 실시간에 같이 실어 보내도록
```


## ★ 문제 파일은 저장소에 없다

`db/002_questions.sql` 에 행사 문제 50개(본 문제 35 · 예비 13 · 패자부활 2)와 **정답**이 들어 있다.
이 저장소는 공개이므로 참가자가 미리 볼 수 있어서 `.gitignore` 로 빼두었다.

- 파일은 따로 보관한다
- `npm run migrate` 를 돌리기 전에 `db/` 폴더에 넣어야 문제가 들어간다
- 파일이 없으면 표와 팀만 만들어지고 문제는 0개가 된다 (오류는 나지 않는다)

배포할 때도 이 파일만 서버에 직접 올린 뒤 migrate 한다.


## 참가 흐름 (PIN 방식)

참가자는 자기 휴대폰으로 등록하지 않는다. 진행측이 등록하고 참가자는 접속만 한다.

1. 참가자가 입장하면 **진행측 노트북**의 `join.html` 에서 팀과 이름을 적는다
2. **PIN 네 자리는 참가자 본인이 직접** 누른다 (오타를 거르려고 두 번 입력)
3. 참가자는 자기 휴대폰에서 `play.html` 로 들어와 **팀 + 이름 + PIN** 으로 접속한다
4. PIN 을 잊으면 진행자 콘솔의 참가자 표에서 **PIN 초기화** → `1234` 로 되돌아간다

PIN 은 진행자 비밀번호와 같은 방식(scrypt)으로 변환해 저장한다. 원문은 어디에도 안 남는다.


## 게임 두 가지 — 퀴즈 / 빙고

진행자 콘솔 맨 위에서 고른다. 누르는 순간 접속한 참가자 전원의 화면이 바뀐다.
두 게임의 진행 상태는 서로 건드리지 않아서, 빙고를 하다 퀴즈로 돌아와도 있던 자리 그대로다.

### 빙고 규칙

- 번호는 **1~50**. 5x5 판에 그중 **25개를 참가자가 직접 골라** 끌어다 놓는다
- 숫자가 많아 한 화면에 다 못 깔므로 `1~10` `11~20` … 묶음 버튼으로 열 개씩 연다
- 진행자가 **배치 마감 · 시작** 을 누르면 그때부터 판을 못 바꾼다
- **번호는 프로젝터에서 참가자가 직접 뽑는다.** 숫자 없는 공이 흩어져 있고,
  하나를 누르면 그때 번호가 정해져 팝업으로 공개된다
- 목표 줄 수(기본 3줄)에 닿으면 진행자 콘솔에 알림과 소리가 뜬다

> 숫자를 고르는 건 화면이 아니라 서버다. 화면에서 고르면 두 사람이 동시에 눌렀을 때
> 같은 번호가 두 번 나오고, 새로고침만으로 다시 뽑을 수 있게 된다.

> 프로젝터에서 공을 누르려면 **진행자 콘솔의 `🖥 프로젝터 열기`** 로 열어야 한다.
> 같은 브라우저라 진행자 쿠키가 같이 가기 때문이다.


## 처음 한 번만 하는 준비

Node.js 22 이상과 PostgreSQL 17 이 필요하다.

```
winget install PostgreSQL.PostgreSQL.17     # PostgreSQL 설치
npm install                                  # express, pg 설치
copy .env.example .env                       # 접속 정보 파일 만들기 (내용 수정)
npm run migrate                              # 표 만들기 + 기본 데이터
npm run create-admin                         # 진행자 계정 만들기
```

`goldenbell-server` 데이터베이스를 미리 만들어야 한다.

```
psql -U postgres -c "CREATE DATABASE \"goldenbell-server\""
```

## 실행 방법

```
npm start
```

브라우저에서 **http://localhost:3000** 에 접속한다.
서버를 끄려면 터미널에서 `Ctrl + C`.

> `npm run migrate` 를 다시 실행하면 표를 지우고 새로 만든다.
> 참가자와 답안이 전부 사라지므로 행사 중에는 실행하지 않는다.

## 혼자 연습해보기

탭 3개를 띄워두면 실시간으로 연결되는 걸 볼 수 있다.

| 탭 | 주소 | 역할 |
|---|---|---|
| 1 | http://localhost:3000/html/login.html | 진행자 로그인 → 콘솔 |
| 2 | http://localhost:3000/html/join.html | 진행측 등록 데스크 |
| 3 | http://localhost:3000/html/play.html | 참가자 휴대폰 |

프로젝터 화면은 진행자 콘솔 오른쪽 위 **🖥 프로젝터 열기** 버튼으로 새 탭에서 연다.

순서:

1. **탭 2**에서 팀 · 이름 · PIN 을 넣고 등록한다
2. **탭 3**에서 같은 팀 · 이름 · PIN 으로 접속한다
3. **탭 1**에서 로그인 → 콘솔 진입 → 문제 선택 및 공개 → 타이머 시작
4. **탭 3**에 문제가 뜬다. 답을 고르고 제출
5. **탭 1**에서 답변 마감 → 판정 확정 → 정답 공개
6. 다시 **문제 선택 및 공개**로 다음 문제를 고른다 (낸 문제는 목록에서 사라진다)

주관식은 자동 채점이 애매하면 `보류`로 남는다. 탭 1의 참가자 표에서
`정답` / `오답` 버튼으로 직접 판정해야 판정 확정을 누를 수 있다.

## 휴대폰으로 접속하기

노트북과 휴대폰이 같은 Wi-Fi에 있어야 한다.

1. PowerShell에서 `ipconfig` → `IPv4 주소`를 확인 (예: `172.30.1.82`)
2. 휴대폰 브라우저에 `http://172.30.1.82:3000/html/play.html` 입력

처음 접속할 때 Windows 방화벽이 물어보면 **허용**을 눌러야 한다.

프로젝터 화면(`screen.html`) 아래쪽에도 접속할 주소가 자동으로 표시된다.

## 데이터가 저장되는 곳

전부 **PostgreSQL** 에 저장된다. 브라우저에는 참가자 번호표 하나만 남는다.

- 어떤 기기에서 접속해도 같은 게임에 참여한다
- 서버를 껐다 켜도 진행 상황이 그대로 남는다
- 참가자가 휴대폰을 새로고침해도 자기 자리로 돌아온다

실시간은 **SSE**(Server-Sent Events)로 전달된다. 브라우저 내장 기능이라
라이브러리가 없고, 연결이 끊기면 브라우저가 알아서 다시 연결한다.

## 관리자 로그인

메인 화면 오른쪽 위 **🔒 관리자** 버튼 → 로그인 화면.
계정은 `npm run create-admin` 으로 만든다. 비밀번호는 변환해서 저장되므로
DB를 열어봐도 원문을 알 수 없고, 잊으면 같은 명령으로 재설정한다.

## 초기화 두 가지 — 헷갈리면 큰일 난다

| 버튼 | 참가자 | 빙고판·부른 번호 | 퀴즈 진행 |
|---|---|---|---|
| **빙고 초기화** (빙고 진행 칸) | 유지 | 지움 | 유지 |
| **전체 초기화** (맨 아래) | **지움** | 지움 | 지움 |

**전체 초기화는 참가자를 지운다.** 누르면 전원이 입구에서 다시 등록해야 한다.
빙고만 다시 돌리려는 것이라면 반드시 `빙고 초기화` 쪽을 쓴다.


## 화면을 고쳤는데 반영이 안 될 때

서버가 화면 파일에 `Cache-Control: no-store` 를 붙이므로 새로고침하면 바로 반영된다.
그래도 그대로라면 `Ctrl + Shift + R`.

프로젝터와 진행자 콘솔은 한 번 열어두고 닫지 않는 화면이라 이 문제가 자주 생긴다.
